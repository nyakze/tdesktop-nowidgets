# tdesktop-nowidgets — форк Telegram Desktop без исполнения JavaScript в виджетах

Это форк [telegramdesktop/tdesktop](https://github.com/telegramdesktop/tdesktop)
(ветка `nowidgets` поверх `upstream/dev`), в котором **виджеты в сообщениях не исполняют JavaScript**.

Мотивация: виджеты Telegram — это HTML + JS в песочнице QuickJS внутри клиента.
Публичные эксплойты позволяли выполнять произвольный код **при одном лишь просмотре сообщения**
(десктоп 7.4.1 / 7.4.2, исправлено в 7.4.3), движок QuickJS-ng регулярно получает новые memory-safety баги,
а отключить виджеты в настройках нельзя. Подробности: `../telegram-widgets-risks.md`
(в выкладке форка — в описании репозитория).

## Что изменено (патч)

Одно место в одном файле — `Telegram/SourceFiles/tgw/tgw_media.cpp`,
функция `Tgw::WidgetMedia::createView()`:

**Было:** при непустом HTML создавался `HistoryView::HtmlWidget`, который поднимал
`Tgw::Runtime` — песочницу QuickJS (исполнение JS).

**Стало:** всегда возвращается `HistoryView::UnsupportedWidget` — готовая карточка
«unsupported message». HTML/JS-рантайм **не создаётся никогда**.

Почему этого достаточно (проверено по кодовой базе):

* `HtmlWidget` конструируется **только** в `WidgetMedia::createView()`;
* `Tgw::Runtime` (сам движок QuickJS) конструируется **только** внутри `history_view_html_widget.cpp`;
* всё остальное в `tgw/` (парсинг, хранилище, скролл, темы) JS не исполняет.

То есть цепочка `сообщение → парсинг → рендер` остаётся целой (виджет-сообщения корректно
показываются как заглушка, удаляются, пересылаются запрещено и т.д.), но исполнение чужого
кода невозможно ни при каком входе.

Что **не** тронуто намеренно:

* QuickJS и `tgw/` остаются в сборке как недостижимый код — патч минимальный и легко ребейзится;
* тесты `test/test_widget_*` (в т.ч. `test_widget_attacks.cpp`) — полезны для проверки;
* прочие векторы атак на клиент (например, `tg://` → `interpret:`, CVE-2026-107181) —
  их закрывают обновления апстрима, поэтому **форк нужно регулярно мержить с `upstream`**.

## Автообновление отключено — и это важно

Апдейтер tdesktop скачивает с `https://td.telegram.org/current` подписанный Telegram'ом
официальный бинарник и **подменяет собой вашу сборку** (независимо от api_id — подпись проверяется
по ключу, зашитому при сборке). Форк «самоисцелился» бы до официальной версии с виджетами.

Поэтому сборка идёт с `-D DESKTOP_APP_DISABLE_AUTOUPDATE=ON` (код апдейтера не компилируется).
Скрипт `build-fork.sh` передаёт этот флаг всегда.

## Сборка (Linux)

1. Получите свои `api_id`/`api_hash`: https://core.telegram.org/api/obtaining_api_id
   (один номер = один api_id; **api_hash не ротируется** — не публикуйте его).
2. Положите креды в `~/.config/tdesktop-fork/api.conf` (не в репозиторий!)
   и закройте файл от чужих глаз (umask по умолчанию делает файлы читаемыми всеми):

   ```bash
   mkdir -p ~/.config/tdesktop-fork && chmod 700 ~/.config/tdesktop-fork
   cat > ~/.config/tdesktop-fork/api.conf <<'EOF'
   export TDESKTOP_API_ID=1234567
   export TDESKTOP_API_HASH=0123456789abcdef0123456789abcdef
   EOF
   chmod 600 ~/.config/tdesktop-fork/api.conf
   ```

   `build-fork.sh` отказывается работать, если файл доступен другим пользователям.

3. Соберите:

   ```bash
   ./build-fork.sh          # init сабмодулей (первый раз, несколько GB) + docker-сборка
   ```

   Бинарник появится в `out/`. Скрипт сначала прогоняет `tools/verify-nowidgets.sh`
   (проверка, что патч не потерян при ребейзе).

Сборка под Windows/macOS — по `docs/building-win.md` / `docs/building-mac.md`,
с теми же двумя флагами: `TDESKTOP_API_ID/HASH` и `DESKTOP_APP_DISABLE_AUTOUPDATE=ON`.

## Сборка через GitHub Actions (все платформы сразу)

В `.github/workflows/{linux,win,mac}.yml` настроена сборка **Release для Linux, Windows и macOS**
на стандартных раннерах (бесплатно для публичного репо) с `DESKTOP_APP_DISABLE_AUTOUPDATE=ON`.

Перед первым запуском добавьте креды в секреты репозитория (они не видны в логах и не попадают в git):

```bash
gh secret set TDESKTOP_API_ID     # значение вводится в prompt
gh secret set TDESKTOP_API_HASH   # значение вводится в prompt
```

Сборка запускается на пуш в ветку (или вручную: Actions → Linux./Windows./macOS. → Run workflow).
Готовые бинарники — в артефактах запуска (хранятся 30 дней).

Для личного использования достаточно Actions: локальная сборка нужна только если хотите
собирать без CI (см. выше) — она требует ~40 GB диска и много часов.

## Поддержка форка (важнее самого патча)

1. **Регулярно мержите апстрим** (раз в 1–2 недели или сразу после security-релизов):

   ```bash
   git fetch upstream
   git rebase upstream/dev      # патч один файл — конфликтует редко
   ./tools/verify-nowidgets.sh  # убедиться, что патч пережил ребейз
   ```

   Конфликты по `README.md` ожидаемы (он намеренно заменён на описание форка) —
   решайте в пользу своей версии (`git checkout --ours README.md`).

2. **Мониторинг безопасности** (форк без обновлений опаснее официального клиента):
   * релизы https://github.com/telegramdesktop/tdesktop/releases ;
   * https://github.com/quickjs-ng/quickjs/issues ;
   * CVE по `telegram desktop` (NVD / OpenCVE / GHSA).
3. **Проверка после сборки:**
   * `tools/verify-nowidgets.sh` — статические проверки патча;
   * ручной тест: тестовый бот шлёт виджет → должна появиться карточка
     «unsupported message», никакого JS (можно смотреть логи `~/.../tdata/` и stdout);
   * при желании — Debug-сборка и прогон `test/test_widget_attacks`.

## Правовой статус

tdesktop — GPLv3 с OpenSSL-исключением. Форк распространяется на тех же условиях:
исходники должны быть доступны получателям бинарника. Не используйте название и логотип
Telegram для этого форка. `api_id`/`api_hash` — ваши личные креды, не включайте их в репозиторий.

## Важные оговорки

* Форк снимает **только** класс атак «JS в виджетах». Он не отменяет необходимость обновлений.
* Мобильные клиенты не покрыты — там свои реализации виджетов.
* Уровень 1 (этот патч) оставляет движок в бинарнике как недостижимый код. Полное вырезание
  (уровень 2, ~25 файлов) описано в `../tdesktop-quickjs-removal-fork.md`, но обычно не оправдано.

## Roadmap / известные ограничения

* **Release-сборка.** Сейчас платформы собираются в Debug-конфигурации — это компромисс:
  апстримовский тулчейн заточен под Debug (Qt с `_debug.a`-суффиксами, MSVC-рантайм `MTd`),
  и Release-линковка на нём падает (LNK1181/LNK2038). Цена — большие артефакты
  (~600 МБ .exe на Windows). Задача: починить Release-линковку (пути к `.lib` в
  prepare.py, выравнивание MSVC-рантайма) либо собирать Qt в Release.
* **Перевод About/intro.** Тексты About и приветственного экрана — свои строки (как у
  Forkgram), без перевода. Если понадобится перевод — подменять строки в языковых
  пакетах при загрузке (пакеты приходят с сервера Telegram, в репо их нет).
